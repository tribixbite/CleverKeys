# Review of everything changed since v1.5.0, and an animated-theme audit (2026-11-14)

Scope: `git diff v1.5.0..bac666c1 -- src/main/kotlin`, 1,405 commits, 527 files, ~133k changed
lines, split into seven batches (file lists by package and size) plus one audit of the animated
backdrops. Eight read-only Fable review agents; nothing was built or run. Each finding below says
how it is known:

- **re-read**: the lead session re-read the cited lines after the report and agrees.
- **traced**: the agent read every link end to end; not re-read by the lead, not executed.
- **plausible**: the code is as described but the trigger depends on framework or device
  behaviour nobody observed.

Two agents found the swipe-ML incognito gap independently (batches 2 and 4).

## 1. Lock screen, direct boot and animated scenes (the maintainer's question)

**The scene path cannot lock a user out (traced).** Every input it reads on show is in
device-protected prefs (`DirectBootAwarePreferences`), static Kotlin objects or APK resources;
paintings are computed in memory with no file, asset, font or database. The one credential-encrypted
read (the migration probe in `DirectBootAwarePreferences.kt:92-97`) is inside a `catch`. A render
failure (`BackdropDrawable.kt:459-465`, `catch (t: Throwable)`) leaves the flat base colour, never a
zero-size or blank keyboard. Expect a flat keyboard for a second or more on a cold process at boot
(the render thread runs at background priority). Not covered by this argument: a crash loop from
ANY cause when CleverKeys is the only enabled IME (the bouncer offers no switcher then); see §4.

Other direct-boot gaps, none a lockout:
- `LanguageAvailability.snapshot()` caches the pre-unlock (empty) pack list for the process
  lifetime: a false "no dictionary" warning and Settings pickers without installed packs until an
  import, delete or restart (`LanguageAvailability.kt:48-57`; plausible).
- Typing-path contractions read pack storage at IME `onCreate` and are never re-synced after
  unlock; pack recovery (voice and language) latches "done" against the unreadable dir
  (`wiring/KeyboardComponentGraph.kt:100-101`, `langpack/LanguagePackManager.kt:149-163`,
  `stt/VoicePackManager.kt:74-89`; plausible).
- The scene animates behind a lock-screen password field (design; `KeyguardManager.isKeyguardLocked`
  in `systemAllowsMotion` would stop it).
