## Outcome

All 18 findings have an implemented repository change. The source-level P1 blockers are closed,
but the release remains **HOLD** until the exact candidate commit passes the new API-34 emulator
gate and fresh per-language CTC evaluation confirms the `ß/œ/æ/ø` projection change. Context
rescoring remains default-off because the available independent confirmation corpus shows no
positive CTC benefit; that is the intended safe resolution, not an enabled feature.

The implementation deliberately does not invent device results, visual baselines, shadow-mode
exposure data, or accuracy/latency numbers. Those remaining measurements are release operations,
listed in [Required release evidence](#required-release-evidence).

## Finding disposition

### CK-150-001 — Resolved: bounded, staged, rollback-safe backup imports

Implemented:

- Encrypted input and decrypted plaintext now have streaming byte ceilings.
- ZIP imports enforce per-JSON, per-media, aggregate decompressed, entry-count, and container limits.
- Entries are staged under `context.cacheDir`; duplicate entries and missing/invalid manifests are
  rejected before live application.
- Unrecognized compatibility entries are drained through the same per-entry and aggregate limits,
  so ignored ZIP members cannot bypass decompression accounting.
- Clipboard rows apply transactionally. Media commit preserves existing files and rolls back both
  replacements and new files when a later operation fails.
- Staging content is removed on success and all failure paths.

Regression coverage includes oversized media, aggregate overflow, missing manifest, duplicate
entries, encrypted input/plaintext limits, partial commit failure, and preservation of existing
media. No `/tmp` path is used.

### CK-150-002 — Resolved in CI definition: accessibility is a real gate; capture is named honestly

Implemented:

- The accessibility job installs both APKs and executes
  `KeyboardAccessibilityInstrumentedTest`, parsing the instrumentation verdict.
- The curated release/device list includes the accessibility and Keystore tests.
- The former “Visual Regression” path is now “Screenshot Capture” and explicitly states that it
  has no comparison baseline.
- Workflow summaries describe node/action/hover/touch assertions and screenshot artifacts without
  claiming visual compliance.

The source compiles locally. Execution of the workflow on the exact release SHA remains required.

### CK-150-003 — Resolved in release workflow: tag publication depends on all critical gates

Implemented:

- A tag commit must be reachable from `origin/main` and match the Gradle version.
- Release waits for pure tests, MockK tests, lint, Android-test compilation, curated API-34
  instrumentation, web parity/smoke/model parity, and a blocking high/critical Trivy scan.
- The ordinary CI Trivy scan no longer has unconditional `continue-on-error`.
- Release source hygiene checks the complete `v1.5.0..HEAD` delta.

No release was triggered as part of remediation.

### CK-150-004 — Resolved: v1.6 metadata matches runtime truth

Implemented:

- `build.gradle` is the version SSoT at `1.6.0`.
- Root and all three ABI Fastlane notes are byte-identical and below the 500-byte target.
- Release notes state that CTC is default, `en/fr/de/es` are validated, `it/pt/sv` are
  provisional, and other language/layout combinations use geometric fallback.
- A drift test pins version/default-engine/language wording and ABI-note parity.

### CK-150-005 — Implemented; held-out device A/B remains a release measurement

Implemented:

- `CtcFuzzyRescue` performs bounded length/initial indexing, capped edit-distance work, a 4,096-word
  maximum scan, and at most two additions.
- Rescue cannot displace a non-empty beam rank one and can populate an otherwise empty slate.
- Replay mirrors the shipping rescue path, including its empty-beam behavior.

Pure tests pin nearest-word recovery, exclusions, distance caps, deterministic scan budgeting, and
rank-one preservation. A held-out sloppy-trace A/B and p95 measurement is still required before
claiming quantitative parity with the removed engine.

### CK-150-006 — Resolved: one encoder pass, two language decodes, rank-only merge

Implemented:

- `InputCoordinator` routes the configured supported secondary language into CTC swipe decode and
  warmup.
- `CtcEngineAdapter` runs the encoder once, independently decodes each language with its own trie
  and preset, and merges ranks without comparing incompatible raw scores.
- Trie/contraction state uses a bounded two-language LRU keyed by normalized language.
- Unit tests cover merge order and duplicate canonical words. Instrumented coverage checks a
  French-primary/English-secondary word against a French-only control.

The instrumentation source compiles locally; the API-34 gate must execute it before release.

### CK-150-007 — Implemented; per-language accuracy confirmation remains required

Implemented:

- Projection now expands `ß → ss`, `œ → oe`, `æ → ae`, and `ø → o` deterministically.
- Canonical display forms are retained and collision choice remains deterministic.
- Frozen French shape expectations were updated to 40,000 records, 0 untypeable records, 37,958
  surfaces, and 2,042 collisions; German and Spanish shapes remain pinned.
- Pure fixtures cover the special expansions and canonical round trip.

Because the reachable vocabulary and collision counts changed, fresh `fr/de/es` and representative
German/Nordic held-out evaluation is mandatory. Do not infer accuracy from compilation or shape
tests.

### CK-150-008 — Resolved: accessibility bounds share finite touch ownership

Implemented:

- Accessibility has a separate finite ownership partition derived from normal hit testing.
- Shifted gaps belong to the next real key; row-edge slop reaches the finite host edge; placeholder
  gaps remain unexposed.
- `Keyboard2View` supplies host width when building virtual bounds.
- Pure geometry tests cover left edge, shifted gaps, right edge, and placeholders; the curated
  instrumentation covers the actual virtual-node provider and activation path.

### CK-150-009 — Safely resolved: keep context rescoring off and improve replay fidelity

## Cross-cutting rules and design context

`AGENTS.md` now records the repository’s private/lightweight/dependable product context, Termux
temporary-output rule, release authority, dirty-worktree handling, import safety invariant, and
accessibility geometry invariant. It also routes release, dictionary, contraction, settings,
emulator, wiki, and clipboard work to the matching repository skills under `.claude/skills/`.

The remediation used the session audit skill for P0–P3 prioritization and scored reporting, and
the repository design-context requirement to document users, brand personality, aesthetic
direction, and design principles. The repository-requested PAL/Gemini architecture reviewer was
not available through the installed tools; changes were therefore kept bounded and compensated
with focused source review, drift tests, and compilation. This is explicitly disclosed rather
than represented as an external review.
