**Companion report:** [2026-08-23-v1.5-delta-audit.md](2026-08-23-v1.5-delta-audit.md)

## 1. Scope and method

This appendix records the evidence behind the findings in the companion report. The review was restricted to work introduced after `v1.5.0`; older behavior is mentioned only where it materially affects the safety or release readiness of the delta. No product code, configuration, tests, release metadata, or existing documentation was edited.

The audit combined:

- a complete `v1.5.0..HEAD` file and commit inventory;
- targeted source review of backup/restore, prediction engines, language handling, accessibility, Android configuration, CI/release automation, documentation, and the web demo;
- project documentation and agent-instruction review before code review;
- JVM test, lint, Android-test compilation, replay, site-build, web parity, web smoke, and browser-demo checks;
- release-metadata, permission, backup-policy, credential-pattern, binary-source, localization, and whitespace checks.

Severity means:

- **P0:** immediate catastrophic risk; stop all affected use.
- **P1:** release blocker or high-impact correctness/security gap.
- **P2:** important follow-up; should be scheduled before or immediately after release.
- **P3:** maintenance or polish issue with limited immediate impact.

## 5. Verification commands and results

Commands below are shown without incidental terminal formatting. No APK assembly was run because the repository-required wrapper writes a root-level build log, which would violate the audit-only write boundary. Focused Gradle verification used the Termux AAPT2 override directly.

### 5.1 JVM tests and lint

```sh
./gradlew runPureTests lintDebug \
  -Pandroid.aapt2FromMavenOverride=/data/data/com.termux/files/usr/bin/aapt2 \
  --stacktrace
```

Result: **BUILD SUCCESSFUL**. `runPureTests` reported **1,743 passed, 0 failed**. Lint reported **0 errors and 13 warnings**, plus two Compose informational findings. Warnings comprised two default-locale conversions, one private-API reflection warning, two plural candidates, and eight unused strings.

The test output also contained an expected coroutine `boom` stack trace and an Android `Build` class exception path even though the suite passed. These make real failures harder to distinguish from expected diagnostics.

```sh
./gradlew runMockTests \
  -Pandroid.aapt2FromMavenOverride=/data/data/com.termux/files/usr/bin/aapt2 \
  --stacktrace
```

Result: **BUILD SUCCESSFUL**, **286 passed**. ByteBuddy logged a transform warning because `androidx.window.java.layout.WindowInfoTrackerCallbackAdapter` was absent while processing `FoldStateTracker`; the tests still passed.

```sh
./gradlew compileDebugAndroidTestKotlin \
  -Pandroid.aapt2FromMavenOverride=/data/data/com.termux/files/usr/bin/aapt2 \
  --stacktrace
```

Result: **BUILD SUCCESSFUL**. This verifies compilation only; it does not show that instrumentation tests were installed or executed on a device/emulator.

### 5.2 Context-rescoring replay

```sh
./gradlew runPureTests \
  -PtestClass=swipe.ContextRescoringReplayTest \
  -PgeoFull=true \
  -PreplayCorpus=device \
  -PreplayMaxCtx=1 \
  -Pandroid.aapt2FromMavenOverride=/data/data/com.termux/files/usr/bin/aapt2
```

Result: **BUILD SUCCESSFUL**. The available device corpus yielded 642 usable samples from 6,589 records, 262 pairable samples, and 719 replay cases.

Key replay observations:

- shipped CTC point: 0 fixes, 0 breaks;
- CTC tuning selected `W=1.00, R=0.50` with 2 fixes and 0 breaks during tuning, but confirmation returned 0 fixes and 0 breaks, so `meetsBar=false`;
- shipped geometric point: 22 fixes, 0 breaks;
- selected geometric point confirmation: 21 fixes, 0 breaks, meeting the configured bar.

This run used locally modified replay sources that were already present in the working tree before the audit. It is evidence about the current checkout, not a clean-HEAD certification.

### 5.4 Static release and hygiene checks

- `git diff --check v1.5.0` found exactly two trailing-whitespace errors:
  - `docs/specs/ctc-architecture-and-multiscript-guide.md:464`
  - `web_demo/specs/index.html:69`
- `build.gradle` still declares version **1.5.0** at the audited revision.
- `RELEASE_NOTES.md` and all three Fastlane listings for version codes `106001`–`106003` describe CTC as opt-in and list only English, French, German, and Spanish.
- Runtime code supports English, French, German, Spanish, Italian, Portuguese, and Swedish, while the latter three are documented as provisional/unmeasured.
- Two Kotlin sources contain literal NUL bytes and are consequently treated as binary by Git:
  - `BackupRestoreManager.kt`
  - `backup/crypto/BackupPassphraseStore.kt`
- The changed-tree credential-pattern scan returned no matches.
- The Android manifest declares no Internet permission. Relevant declarations were vibration, a commented recording permission, and user-dictionary read access.
- Backup/data-extraction rules use a strict allowlist and exclude the passphrase preference file.

## 7. Positive evidence

The delta contains substantial valuable work that should be retained while the blockers are addressed:

- pure and mock JVM suites pass at significant scale;
- Android instrumentation sources compile;
- lint has no errors;
- no Internet permission or changed-tree credential signature was found;
- backup exclusions are intentionally narrow;
- the geometric engine showed a strong no-regression result in the available replay;
- app/web CTC model parity and smoke checks pass;
- the static site builds successfully;
- several issues recorded in older audits are now fixed, including Greek-script handling, CTC trie fan-out clamping, explicit fallback UI, beam-setting validation, ONNX session closing, model cleanup, and improved language descriptions.

## 8. Limitations

- No release or debug APK was assembled because doing so through the required Termux wrapper would create a log outside the user-authorized documentation directory.
- Android instrumentation was compiled but not executed on a device/emulator during this audit. In particular, accessibility behavior was established by source/gate review rather than a local TalkBack run.
- The context replay covered the available device corpus with one context setting, not every corpus and configuration combination.
- Existing working-tree modifications mean replay evidence describes the checkout as supplied, not solely committed `HEAD`.
- No external GitHub Actions run, store listing, release asset, or deployed website state was inspected; workflow conclusions come from checked-in automation.
- Browser-demo success should not be interpreted as a clean console because the harness recorded a favicon 404 without failing.
- Site duplicate-ID warnings may be influenced by ignored incremental cache state; they were not elevated to a release finding without a clean-room reproduction.
