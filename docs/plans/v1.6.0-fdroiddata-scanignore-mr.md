# fdroiddata MR needed before the v1.6.0 tag (scanignore drift)

**Status**: BLOCKING the v1.6.0 F-Droid auto-build. Found by the 2026-09-09 release
sanity check. The maintainer posts this MR (external platform — not automated).

## Problem

F-Droid's checkupdates bot clones the newest Builds block's `scanignore` when it
appends the 1.6.0 blocks. The 1.5.0 blocks ignore exactly one wordlist
(`scripts/data/aosp_en_wordlist.txt.gz`). Since v1.5.0 the repo added **11 more**
`scripts/data/aosp_*_wordlist.txt.gz` files (de, el, es, fr, he, it, nl, pt, ru,
sv, tr) and `web_demo/demo/models/ctc_vocab.bin` — all outside the current
scanignore/scandelete set, so the scanner will fail the 1.6.0 build.

## Fix — MR against gitlab.com/fdroid/fdroiddata, metadata/tribixbite.cleverkeys.yml

In **each of the three 1.5.0 Builds blocks** (105001/105002/105003) — the templates
the bot clones — change:

```yaml
    scanignore:
      - scripts/data/aosp_en_wordlist.txt.gz
      - scripts/langpack-sv.zip
      - scripts/dictionaries/langpack-*.zip
      - scripts/dictionaries/en/en_enhanced.bin
      - src/main/assets/dictionaries/*.bin
      - src/main/assets/prefix_boosts/*.bin
```

to:

```yaml
    scanignore:
      - scripts/data/aosp_*_wordlist.txt.gz
      - scripts/langpack-sv.zip
      - scripts/dictionaries/langpack-*.zip
      - scripts/dictionaries/en/en_enhanced.bin
      - src/main/assets/dictionaries/*.bin
      - src/main/assets/prefix_boosts/*.bin
      - web_demo/demo/models/*.bin
```

(Two changed lines: the en-only wordlist entry becomes the `aosp_*` wildcard, and
one new entry covers the web-demo vocab binary. If the 1.6.0 blocks already exist
by the time the MR is made, apply the same change there instead.)

## MR description text (suggested)

> tribixbite.cleverkeys: widen scanignore for 1.6.0
>
> Upstream added per-language AOSP wordlists (`scripts/data/aosp_*_wordlist.txt.gz`,
> build-time dictionary sources, same provenance as the existing `aosp_en` entry)
> and a web-demo vocab binary (`web_demo/demo/models/ctc_vocab.bin`, not part of
> the Android build). Both trip the scanner; neither ships in the APK build path
> differently than the already-ignored equivalents.
