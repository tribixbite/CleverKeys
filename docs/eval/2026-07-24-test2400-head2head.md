# Same-split head-to-head — FUTO 2,400-row test set (2026-07-24)

Rigorous, apples-to-apples comparison of three swipe decoders on **one identical trace
set**: the FUTO held-out test split `~/storage/shared/swipedata/test_hwsfuto.jsonl`
(N = 2,400). Supersedes the directional comparison in
`docs/eval/futo-decoder-eval-notes.md`, whose engine numbers came from different splits.

## Provenance & method

| Engine | Config | Cache |
|---|---|---|
| **our neural** | shipped ONNX transformer, production path `--frame-remap identity --training-features --production` (trie-constrained beam **width 6**, GNMT α=1.4, conf/freq rerank) — the exact path validated at 76.34% in `2026-07-24-swipedata-onnx-validation.md` | `test2400_neural.jsonl` |
| **our geo** | geometric SHARK2 (`GeometricEngineConfig()` shipped defaults), `GeoFutoTrain100kReplayTest` in `GEO_ALL_ROWS` mode | `test2400_geo.jsonl` |
| **FUTO floor** | FUTO's own encoder `honorable_sturgeon` (.pte, ExecuTorch), textbook trie-CTC beam — see the floor eval | `futo_decoder_test2400.jsonl` |
| **FUTO ceiling** | FUTO encoder + `magic_macaw` decoder + optimized beam | _pending — separate agent running_ |

- **Trace set**: all 2,400 rows, original file order, keyed by `idx` 0..2399
  (`scripts/convert_test2400_aligned.mjs` → `test2400_ordered.jsonl.gz`, no shuffle, no
  word-filter, target lowercased).
- **Scoring**: each engine is scored against **its own vocabulary**; an OOV target simply
  counts as a miss (identical treatment across engines → apples-to-apples). OOV vs our
  98,140-word `en_enhanced`: **64 / 2,400 = 2.67%**; OOV vs FUTO's 131,544-word lexicon:
  99 / 2,400 = 4.13%.
- **Neural OOV handling**: the `--production` harness skips OOV targets (a trie-constrained
  beam can never emit them), emitting 2,336 in-dict lines in order;
  `scripts/test2400_metrics.py` maps neural line k → the k-th in-dict `idx` and scores the
  64 OOV as neural misses (verified: neural word-sequence == the in-dict subsequence, 0
  mismatches).
- Run on-device (Termux ARM64), neural 4 threads (~17 min), geo ~7.9 ms/trace.

## Headline — top-1 / top-3 / top-5, micro (all 2,400; OOV = miss)

| Engine | overall | ≤3-char (n=815) | 4+-char (n=1585) |
|---|---|---|---|
| **FUTO floor (enc-only)** | **79.25 / 87.71 / 89.58** | 82.45 / 91.29 / 93.25 | **77.60 / 85.87 / 87.70** |
| **our neural (beam6)** | 74.62 / 84.33 / 87.42 | **89.45 / 95.46 / 96.32** | 67.00 / 78.61 / 82.84 |
| **our geo (SHARK2)** | 67.50 / 78.88 / 81.79 | 69.33 / 81.60 / 85.28 | 66.56 / 77.48 / 80.00 |

Macro top-1 (58 words with ≥5 examples): neural **93.26%**, FUTO 83.28%, geo 69.23%
(macro over-weights frequent — mostly short — words, where neural dominates).

### The stratum split is the story
- **Short words (≤3): our neural wins decisively** — 89.45% vs FUTO 82.45% vs geo 69.33%.
  Our production pipeline's frequency/context priors resolve tiny-swipe ambiguity better
  than a pure trajectory model.
- **Long words (4+): FUTO wins decisively** — 77.60% vs our neural 67.00% vs geo 66.56%.
  FUTO's TCN encoder + lexicon beam track long trajectories far better; this is exactly
  where our transformer's CTC-style long-word decode degrades.

honest cross-engine picture, not deflated by corpus choice.

## Fusion union ceiling (go/no-go input for `hybrid-engine-rank-fusion.md`)

Union@k = fraction where **at least one** engine ranks the target within top-k — the
**ceiling** a perfect oracle fuser could reach (a real fuser captures only part of it).
Verdict rule: union@1 headroom over the best single engine ≥ ~2 pt ⇒ real complementarity
worth fusing.

**Our hybrid (neural + geo):**

| Stratum | union@1 | best single@1 | headroom@1 | union@3 | verdict |
|---|---|---|---|---|---|
| overall | 84.75 | 74.62 | **+10.12** | 91.21 | **GO** |
| ≤3-char | 92.02 | 89.45 | +2.58 | 96.69 | GO |
| 4+-char | 81.01 | 67.00 | **+14.01** | 88.39 | **GO** |

**All three (neural + geo + FUTO):**

| Stratum | union@1 | best single@1 | headroom@1 | union@3 |
|---|---|---|---|---|
| overall | 89.67 | 79.25 | +10.42 | 93.58 |
| ≤3-char | 93.62 | 89.45 | +4.17 | 97.42 |
| 4+-char | 87.63 | 77.60 | +10.03 | 91.61 |

**Verdict: fusion is a strong GO on every stratum**, and biggest exactly where each engine
is individually weakest — **+14.0 pt of oracle headroom on long words** for our own two
engines. Neural and geo make *different* long-word errors, so a confidence-aware fuser has
substantial room to lift 4+-char top-1 from ~67% toward the ~81% union ceiling. Caveat: the
union is the upper bound, not the achievable — whether a real fuser captures it depends on
how separable the engines' confidence signals are; that is the next experiment.

## Caveats
- FUTO's row here is the **encoder-only floor (79.25%)**; its paper reports 92.54% with the
  full C++ beam + `magic_macaw`. The ceiling row is being computed and will be added.
- Union headroom is an oracle ceiling, not a realizable fusion accuracy.
- Neural/geo/FUTO in-vocab numbers are over different subsets (different vocabularies) and
  are context only — the all-2,400 table is the cross-engine comparison.

## Reproduce
```
node scripts/convert_test2400_aligned.mjs
python3 tools/test_cli_predict.py --corpus ~/.cache/cleverkeys-test/test2400_ordered.jsonl.gz \
  --frame-remap identity --training-features --production --beam 2 --threads 4 \
  --skip 0 --limit 2400 --out ~/.cache/cleverkeys-test/test2400_neural.jsonl
GEO_ALL_ROWS=true FUTO100K_IN=test2400_ordered.jsonl.gz FUTO100K_OUT=test2400_geo.jsonl \
  sh gradlew runPureTests -PtestClass=swipe.geometric.GeoFutoTrain100kReplayTest -PgeoFull=true
python3 scripts/test2400_metrics.py
```
