## The geometric-removal question

> **Corrected 2026-08-19.** An earlier version of this section claimed "37 of 86 bundled layouts
> don't declare `script="latin"`" and that non-Latin layouts "can only be served by geometric".
> **Both are wrong**, and the guide's §2.1 and §3 say so with measurements. The error was
> computing `86 − 49 = 37` and calling the remainder "undeclared", which conflated *declared
> non-Latin* with *no script attribute at all*. Verified census below.

**The layout census** (`src/main/layouts/`, 86 XML — the tree `copyLayoutDefinitions` actually
ships; `srcs/layouts/` is divergent and **not** read by any build task):

| bucket | count | routing |
|---|---|---|
| `script="latin"` **and** a–z-complete | **46** | CTC — the intended set |
| `script="latin"` but a–z-incomplete | **3** | geometric, stopped by the alphabet gate |
| non-Latin declared (15 distinct scripts) | **35** | geometric at gate 1 |
| no `script` attribute at all | **2** | `numeric.xml`, `pin.xml` — not letter layouts |

Only **two** layouts lack a script attribute and neither is a letter layout. Of the three
latin-declared-but-incomplete, `latn_qwerty_az` and `latn_qwerty_tly` genuinely lack `w`;
**`grek_qwerty.xml` is MIS-DECLARED `script="latin"` — verified live in the shipped tree.** The
`6af11da7` fix that claimed to close this landed in `srcs/layouts/`, which the build does not
read. No user-visible impact (the alphabet gate catches it), but gate 1 of 3 is being relied on.

**"Non-Latin can only be served by geometric" is false.** Per-script models are *required* — a
Latin-trained encoder does not zero-shot another script, because motor statistics and the
implicit character-transition prior are learned even though geometry is an input — but they are
**cheap and proven**: ~94 k steps of `resbn:80`, under an hour on one RTX 5080, from just a word
list and the layout geometry. No corpus licensing, no human subjects. `phaseIB-ru-synth` saw
**zero real Cyrillic rows anywhere** (synthetic val split too) and decodes real Russian swipes at
in-dict top-1 **77.41** — the same class as geometric's cross-layout anchors (71–77).

Equally, **"CTC's ALPHABET is hardcoded a–z" is true of two constants in one adapter file and
false of everything else.** The model has no alphabet at all: the head is 64 geometry-conditioned
slots plus blank, and `keyEmbed` is a function of `(cx, cy)`, never of the slot index. `CtcLayout`,
`CtcLexiconTrie` (bound is `MAX_KEYS`=64, not 26) and `CtcEmissions.sliceFromHead` (takes
`numLetters` as a parameter) are already script-generic. The `MAX_CHILDREN` clamp removal
(`d671d19e`) is called out in the guide as "the single most important piece of pre-work that is
already done" — **a 31/33-letter Cyrillic trie is safe in shipped code today.**

**Russian is DELIVERED, artifacts committed** — `CleverKeys-ML/ctc/artifacts/`:
`ru_synth_ch80_fp16w.onnx` **589,406 B** (sha `84ac284d…`) plus its golden fixture. NOTE: the
local ML checkout was **15 commits behind** on 2026-08-19 — `git fetch` before concluding
anything is missing. Remaining work is app-side only (guide §4.6): per-script `ALPHABET` +
`buildMappedLayout`, a **second `MODEL_ASSET`** with a language→model mapping (the adapter has
exactly one today), the ru langpack, a golden-fixture row in `CtcParityTest`, and on-device
latency/memory.

So the honest answer: geometric is removable **script by script**, and each script costs about an
hour of GPU plus the app-side wiring above. What it cannot be is removed *first*. Deleting it
today does not downgrade a Cyrillic user — it removes their swipe.

### The multi-script wiring plan already exists — `CleverKeys-ML/ctc/PHASE_O.md` §3

Six scripts are specified end to end (ru, el, uk, bg, mk, he) with per-script alphabet strings,
K, lexicon status and preset. Read §3.2 before designing anything; the essentials:

- **Slot order IS the alphabet array.** Every Phase-O layout json lists letters in
  **codepoint-sorted** order and emission column `c` is `letters[c]`. The app's per-script
  `ALPHABET` must be that exact string in that exact order, or **every decode is silently
  permuted** — no crash, just wrong words. This is the sharpest footgun in the whole plan.
- **The geometry needs no app-side change.** `app_layout.py` replicates
  `KeyboardGeometry.computeKeyRects` + `buildMappedLayout` and reproduces `en_qwerty.json` from
  the app's own XML to 4.7e-4, so the `layout_keys` the app computes at runtime *is* what the
  models trained on. Locale extra keys and the number/bottom rows do not perturb it.
- **Eight changes are enumerated**; two are already done — the trie width (`d671d19e`) and
  `CtcLayout`'s generic `alphabet: CharArray`. The live ones are per-script `ALPHABET`,
  per-script routing, a per-language **model asset** (`MODEL_ASSET` is one constant),
  runtime-extensible `SUPPORTED`, a reachable `tunedRuCkdt` (it exists but `presetFor` can never
  return it), and a per-script fixture↔model↔preset row in `CtcParityTest`.
- **Per-script projection rules the app must mirror** (§3.4) — all scripts lowercase and strip
  `- ' ’ ʼ ‘ \``; el/he NFD + drop marks + NFC; **ru/bg/mk must NOT use NFD** (it decomposes
  й into и + breve) and use character folds instead (ru ё→е, ъ→ь); el word-final σ→ς; uk rejects
  words containing ї or ґ as untypeable (4.03% of vocabulary).
- Lexicon status: ru importable today, el needs the sigma repair, **uk/bg/mk/he must be built**,
  and he additionally needs a new `hebrew` branch in `build_wordlist._is_script_word` (it
  currently raises on anything but latin/greek/cyrillic).

**Two app fixes are named as prerequisites to ALL of it** (§3.3) — both are in this handoff:
item 10 (the Greek script attribute) and the Greek final-sigma repair, below.

### NEW — Greek final sigma, 25.7% of the pack

Either regenerate `langpack-el` with `ς` preserved, or apply the deterministic repair at trie
build: a word ending in `σ` gets that `σ` rewritten to `ς`. **One Greek word in four is affected.**
Without it the model is scored against the wrong key in the wrong row, while the *user* swipes to
ς because that is where Greek orthography puts it. Blocks Greek entirely; harmless to fix early.

**Tier note to carry**: Colemak specifically and arbitrary user XML generally were **never
benchmarked**. They are covered by design (geometry input + arbitrary-arrangement augmentation)
and the worst *measured* layout is german at 81.30 against geometric's ~77, so the expected-value
case is strong — but "Colemak ≥ geometric" is an inference, not a measurement. Say it that way.

## Rules that must not be broken

1. **No Yandex data** in any training run or shipped artifact — eval-only by licence. `ru-real`
   at 89.64 is better than everything else and permanently unusable.
2. **No FUTO weights or outputs** in anything we train or ship. Corpus + decode-algorithm lineage
   are the permitted inheritance; `NOTICE:46-64` states it correctly — do not "improve" it.
3. **Respect evidence tiers in prose.** "test-validated" = decoded on a sealed split whose read
   was spent from the ledger. Everything else is val-only. Russian is val-only permanently, and
   it/pt/sv are `PROVISIONAL`. Quoting a val-only finalist's number as the ship model's is
   exactly how the `sw2345` misattribution happened — **twice**.
4. **Never route a non-Latin script to CTC** without all three of: a per-script model, a
   per-script trie at the app's own frequency scale, and a golden fixture.
5. **Testing policy**: never test locally via ADB (build-install and log-read only). Write ew-cli
   instrumented or pure JVM tests; if untestable, ask.
6. **`sh gradlew`**, not `./gradlew` (Termux shebang). Temp files go in the session scratchpad,
   never `$TMPDIR`/`$PREFIX/tmp`. Use `rg`, not `grep`.
7. **Rebuild BOTH APKs before an ew-cli run.** `assembleDebugAndroidTest` alone leaves a stale
   app APK and you get `NoSuchMethodError` for code you just wrote. Cost one full run to learn.
